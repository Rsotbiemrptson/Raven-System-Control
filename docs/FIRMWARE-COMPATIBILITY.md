# Firmware bases and feature requirements

AYN firmware **1.0.0.187** is the Odin 3 base discussed here. **188, 189, 189 r2 and 190 are Raven's local modified-build labels, not additional AYN firmware releases.** They identify test configurations derived from 187. A Game Assistant version such as `2.0-raven.190.3` is an application version, not a firmware requirement named "190.3".

Odin 2 is separate: its verified target is AYN firmware **400**, Android 13/API 33. Do not apply the Odin 3 numbering to Odin 2.

## Can the app run on unmodified firmware?

**Yes for the supported core-control route; no release changed the whole app into a modified-firmware-only app.** The APK runs as a normal Android application and uses AYN's existing `PServerBinder` privileged service for hardware commands. Core fan, whole-ring LED and standard-tile behavior was tested on stock Odin 3 firmware 187 in 0.2.29. This does not certify every later feature on an unmodified 187 device: recent complete device tests used the modified 187-based system.

The app does not supply a missing OEM privileged service or a general `su` fallback. Hardware access must pass Guided Setup and live interface checks. Running the UI alone does not establish hardware compatibility.

| Feature | What must be present | Modified firmware dependency |
| --- | --- | --- |
| Fan control, fan profiles, whole-ring LEDs, LED profiles and recovery | AYN privileged service, readable sensors and writable expected fan/LED interfaces | No new firmware component is required by the app. The latest complete stock-187 regression remains to be performed. |
| CPU/GPU modes and frequency limits | Odin 3/API 35/CQ8725S, expected CPU clusters and supported frequency tables, writable cpufreq/KGSL controls through the OEM service | No added kernel or Game Assistant component is required for the app's own controls. Available stock operating points limit the choices; the APK does not add overclocking frequencies. Recent complete guard tests were on modified 187. |
| Individual Odin 3 ring segments, from 0.2.51-preview | Existing HTR3212 controllers, writable LED enable nodes and privileged access to the detected I2C devices | Uses an APK-provided native helper, not a new kernel driver. It was validated on modified 187; direct I2C access and complete segment behavior on unmodified 187 still need validation. Do not assume stock qualification from the absence of a version gate. |
| Raven Fan/LED/CPU tiles with the standard Android popup | The app's tile services and the same supported hardware access | No modified SystemUI is required. On stock Odin 3, the normal chooser closes the shade. |
| Raven profile choosers above the Odin 3 shade | Modified SystemUI exposing `dev.raven.systemui.profilehost` and compatible trusted profile-dialog dispatch | Requires that SystemUI extension. Without it, the app falls back to the standard popup. |
| Raven controls in Game Assistant and per-game application/restoration | Modified system Game Assistant with Raven selectors, foreground-game tracking, profile-bridge calls and stock/Follow-global ownership handoff; compatible system identity/permissions | Optional firmware/system-app integration. The bridge appeared in local 0.2.44-preview and first shipped publicly in 0.2.49-preview. Stock Game Assistant does not gain these hooks by installing Raven alone. |
| OEM per-game fan selection shown in Raven Fan subtitles, from 0.2.63-preview | Game Assistant must report its per-game fan mode through `sync_game`/`odin_fan` after selection and game transitions | Requires the added modified Game Assistant reporting; tested app version `2.0-raven.190.3`. Without it, Raven retains the existing global fan status. |
| Silent successful fan handoffs and safety fallbacks, from 0.2.64-preview | Existing supported fan control and recovery path | No additional firmware extension. Failed or unconfirmed recovery still alerts. |

CPU/GPU controls were developed in local 0.2.38-era builds. Older local performance build-label checks were removed in 0.2.49-preview in favor of platform/interface checks. That restriction did not mean a new AYN firmware base was necessary.

The modified Game Assistant and SystemUI are separate system components; they are not bundled in the Raven System Control APK. Core control does not require replacing either. These extensions must have the appropriate system identity and permissions; installing an unrelated normal APK does not provide them. Raven does not disable SELinux or flash firmware to obtain access.

## Remaining stable-release checks after 0.2.64-preview

- Run the current APK's changed fan/recovery-notification paths on Odin 2 stock firmware 400; the last full Odin 2 acceptance was on an earlier app build.
- Check current-build custom fan control through Odin 3 standby/background operation and the Game Assistant per-game safety-fallback/handoff path. The published 0.2.63-preview passed OEM modes/subtitles after standby; 0.2.64-preview's notification changes have passed a live handoff, a controlled temperature fallback and a simulated failure-alert check, but not this full current-build lifecycle combination.
- If advertising complete current stock-187 support, qualify the current APK on an unmodified 187 device, especially direct ring segments and standard chooser fallbacks. Otherwise publish a clearly limited compatibility statement rather than claiming that test passed.
- Build the stable candidate after these checks and perform a short exact-APK install/upgrade and affected-feature check, preserving saved settings, profiles and recovery backup. Unchanged LED/CPU features do not need every historical test repeated without a new reason.

This documentation correction does not rebuild APKs, change installed firmware, alter safeguards or change historical release assets/checksums.
